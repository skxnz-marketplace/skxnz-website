# Buyer UI regression debt

Founder feedback records that the admin dashboard and operations surfaces are strong, while the buyer-facing site now feels visually worse than the earlier experience. This is a **High** launch-quality debt item.

D9-A deliberately does not attempt a buyer UI redesign: doing so would expand a build-proof task into a subjective, high-surface-area change without browser review. A dedicated buyer UI recovery sprint should audit the home, shop, product, cart, checkout, account, and mobile visual hierarchy against approved references; restore the strongest earlier direction where evidence supports it; and run desktop/mobile/keyboard screenshot review. It must retain the existing truthful private-preview/payment/delivery language.
